# 巡检缺陷命名分类工具：完整原生复刻实施计划

## 1. 交付目标

将 `巡检缺陷命名分类工具_怀旧版.html` 的全部可用功能迁移为 Windows 原生桌面软件，最终用户不再需要打开 HTML 文件。

验收原则：

- 原 HTML 可执行的功能，原生版都必须可执行。
- 原 HTML 生成的目录结构、文件命名和分类结果保持一致。
- 原 HTML 的快捷键、鼠标操作、筛选、统计和设置均有对应实现。
- 原生版可脱离浏览器、网络和 Office 运行。
- 不保留旧版浏览器兼容层，不把 HTML 嵌入软件，不提供半成品 fallback。

## 3. 原生实现架构

技术栈：

- C#、.NET 8
- WinUI 3 / Windows App SDK
- SQLite
- Windows Imaging Component
- Win2D 或原生 Direct2D 画布
- ClosedXML
- MSIX 或 unpackaged self-contained 发布

项目结构：

```text
src/
├─ PatrolDefect.App
├─ PatrolDefect.Application
├─ PatrolDefect.Domain
├─ PatrolDefect.Infrastructure
└─ PatrolDefect.Imaging
```

新增 `PatrolDefect.Imaging`，专门处理图片解码、缩放、画布变换、标注渲染和成果图导出，避免把图像细节塞进窗口代码。

## 5. 关键行为规格

### 5.1 文件命名

从 HTML 中提取并单元测试以下规则：

- 线路前缀。
- 杆塔号。
- 部件/位置。
- 缺陷描述。
- 多处缺陷序号。
- 原图名和圈示图名的对应关系。
- 重命名后的目录和文件映射。
- 中文括号、下划线、空格、连接符和数字后缀处理。

这些规则必须集中在 `FileNameRuleService`，禁止散落到 UI 事件中。

### 5.2 输出一致性

每次保存采用：

1. 计算目标路径。
2. 校验目录和文件名。
3. 写入临时文件。
4. 校验文件存在且可读取。
5. 替换目标文件。
6. 写入数据库输出记录。
7. 更新统计。

中间失败时不得留下数据库已保存、文件未生成的假状态。

### 5.3 取消标记

取消当前照片时：

1. 删除该照片关联的所有圈示图、原图和危急成果。
2. 删除标注、标签和输出映射。
3. 清除照片已标记状态。
4. 保留已看状态。
5. 刷新目录树和统计。
6. 重新加载纯净原图。

## 8. 完成定义

在以下条件全部满足前，不称为“已完成”：

- 第 2 节所有功能均有原生实现。
- 规则和文件输出测试通过。
- 同一批输入照片与 HTML 输出结果一致。
- 关闭并重启后状态可恢复。
- 没有依赖浏览器或 HTML。
- GitHub Actions 能生成可下载的 Windows 安装包或自包含发布包。
- 完成一次真实巡检目录的全流程试用。

## 9. 当前代码处理原则

现有 `src` 中的初始 WinUI 骨架只能作为工程起点，不能视为已完成版本。后续实现将优先补齐规则、文件输出、画布和状态恢复；在完整复刻前不发布“可替代原 HTML”的版本。
