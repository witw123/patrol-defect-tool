# 阶段 1：数据与文件基础设施

## 目的

建立不依赖 UI 的项目、照片、标注和成果文件基础能力。

## 实现任务

1. 建立 SQLite 数据库及表结构。
2. 保存输入目录、输出目录和项目更新时间。
3. 递归扫描图片并生成相对路径索引。
4. 过滤 `缺陷圈示图`、`缺陷原图`、`危急缺陷` 等成果目录。
5. 实现文件复制、临时写入、替换、删除和重命名。
6. 实现 manifest 或等价数据库映射。
7. 为全部文件操作加入日志和异常结果。

## 产出

- `ProjectStore`
- `PhotoScanner`
- `FileOperationService`
- `OutputManifestStore`
- 数据库集成测试

## 完成标准

同一相对路径只产生一个照片记录；重启后项目和输出映射可恢复；单个坏文件不会中断批处理。

## 当前实施证据

- 相对路径 upsert 保留照片 ID；重扫、顺序改变、重启的集成测试通过。
- 成果保存先完成两个临时文件，提交采用不覆盖的文件移动；后一步失败时清理本次已提交原图。
- 坏图和已取消任务不留下半套成果；命名分配同时检查原图、圈示图两个目录，避免覆盖单边已有文件。
- 标注集合在 SQLite 事务内替换；跨照片 ID 冲突回滚，不因重复保存累积旧框。
- 输出像素测试验证尺寸、红框位置、10 像素线宽、纯净原图字节不变。
- 本轮全解决方案 Release 编译通过，58 项测试通过。

批处理逐文件异常结果、普通保存覆盖与二次编辑分支。现有临时文件提交不等于跨资源原子事务。
